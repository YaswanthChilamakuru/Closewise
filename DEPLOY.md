# Deploying Closewise to Render (free web service)

Closewise runs as **one Node web service**. Express serves:

| Path | What |
|---|---|
| `/health` | Liveness probe: plain-text `ok`. Never touches the database. |
| `/api/*` | JSON API |
| `/mcp/:token` | MCP endpoint (Streamable HTTP, stateless) for the user's Claude |
| `/p/:slug` | Public proposal pages for clients |
| everything else | The built React app (`web/dist`), with SPA fallback to `index.html` |

The SPA fallback never answers `/api`, `/mcp`, `/p` or `/health`. It also skips requests for
missing files (any path with an extension, e.g. a stale `/assets/*.js`), so those get a real 404.

The database is **Neon Postgres** (external). Render's free disk is wiped on every restart, so nothing is stored locally.

---

## 1. Prerequisites

- The repo pushed to GitHub or GitLab.
- A Neon project. Copy the **direct** connection string (host *without* `-pooler`), with `?sslmode=require`.
  `prisma migrate deploy` needs a direct connection: Neon's pooler (PgBouncer) breaks migrations.

## 2. Create the service from the Blueprint

1. Render dashboard → **New → Blueprint** → pick this repo. Render reads `render.yaml`.
2. It asks for the env vars marked `sync: false`:
   - `DATABASE_URL`: the Neon direct connection string.
   - `APP_URL`: `https://<service-name>.onrender.com` (no trailing slash). The service is named
     `closewise` in `render.yaml`, so this is normally `https://closewise.onrender.com`. If that
     name is taken Render adds a suffix, so check the URL after creation and update `APP_URL` if needed.
3. `JWT_SECRET` is generated automatically. `NODE_ENV`, `NODE_VERSION` and `NPM_CONFIG_INCLUDE` are preset.
4. **Apply**. The first deploy runs:

   ```
   build:  npm install && npm run build
           → web: tsc --noEmit && vite build          (outputs web/dist)
           → server: prisma generate && tsc           (outputs server/dist)
   start:  npm start
           → prisma migrate deploy                    (applies pending migrations, safe to re-run)
           → node server/dist/index.js                (listens on $PORT)
   ```

   Render then polls `GET /health` until it returns 200.

### Environment variables

| Var | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes | Neon **direct** URL, `?sslmode=require` |
| `JWT_SECRET` | yes | Long random string (auto-generated by the Blueprint) |
| `APP_URL` | yes | Public base URL. Every `editUrl`/`publicUrl` returned by MCP tools is built from it. The server logs a warning if it still points to localhost in production. |
| `NODE_ENV` | preset | `production` |
| `NPM_CONFIG_INCLUDE` | preset | `dev`. `NODE_ENV=production` would otherwise make `npm install` skip devDependencies (TypeScript, Vite, Tailwind) and the build would fail. |
| `NODE_VERSION` | preset | `20` |
| `PORT` | auto | Set by Render, don't set it yourself. |

## 3. Seed (optional) and connect Claude

Seeding creates a demo user and prints that user's MCP URL. Run it once, from your machine, against the production DB:

```bash
# with DATABASE_URL and APP_URL in .env set to the production values
npm run db:seed
```

Then in claude.ai: **Settings → Connectors → Add custom connector**, URL:

```
https://<your-app>.onrender.com/mcp/<mcpToken>
```

The token is a secret: anyone who has the URL can act as that user. Treat it like a password.

## 4. Verify

```bash
curl https://<your-app>.onrender.com/health          # → ok
curl -I https://<your-app>.onrender.com/              # → 200 text/html
curl https://<your-app>.onrender.com/api/ping         # → {"ok":true}
```

Then ask Claude to list your proposals. The URLs it returns should start with your Render domain, not `localhost`.

## Free-tier behaviour to know about

- **Spin-down:** the service sleeps after about 15 minutes without traffic. The next request (e.g. a client opening
  `/p/:slug`, or Claude calling an MCP tool) waits roughly 30–60 s for a cold start, and `prisma migrate deploy`
  runs again at every start (a quick no-op when nothing is pending). Neon also suspends idle compute, so the
  first DB query after a sleep adds a second or two.
- `/health` deliberately skips the database, so a slow Neon wake-up can't fail Render's health check and trigger a restart loop.
- **Shutdown:** on SIGTERM (deploys, spin-down) the server stops accepting new connections, finishes in-flight requests and closes the DB pool.
- `trust proxy` is set to 1 hop (Render's proxy), so `req.ip` and `req.secure` reflect the real client and HTTPS.

## Migrations workflow

- Locally: change `server/prisma/schema.prisma`, then `npm run db:migrate -- --name <change>` and commit the new folder under `server/prisma/migrations/`.
- On deploy, `npm start` applies it with `prisma migrate deploy`. If a migration fails, the server process never starts and the deploy is marked failed in Render's logs.
- Never use `prisma migrate dev` or `db push` against production.

## Running the production build locally

Create `.env` in the repo root (git-ignored; Render doesn't use it, it uses dashboard env vars):

```bash
DATABASE_URL="postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require"  # direct, non-pooler
JWT_SECRET="any-long-random-string"
APP_URL="http://localhost:3000"
```

```bash
npm run build
npm start                   # migrate deploy + start, reads ../.env
npm run serve -w server     # start only, skips migrations
```

Open http://localhost:3000. Stop `npm run dev` first if it's already using port 3000.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Build fails: `tsc: not found` / `vite: not found` | `NPM_CONFIG_INCLUDE=dev` is missing (devDependencies were skipped). |
| Start fails: `P1001 Can't reach database` | Wrong `DATABASE_URL`, or it uses the `-pooler` host. Use the direct host with `sslmode=require`. |
| `P1001` from `prisma migrate` **locally**, while the app itself connects fine | Your network has broken IPv6. Neon resolves to IPv6 too, and Prisma's engine tries it first while Node falls back to IPv4. Make Windows prefer IPv4 (admin PowerShell: `netsh interface ipv6 set prefixpolicy ::ffff:0:0/96 60 4`, then restart the terminal), or fix IPv6 on the router. Undo with `netsh interface ipv6 set prefixpolicy ::ffff:0:0/96 35 4`. |
| Start fails: `P3009 failed migrations` | A previous migration failed halfway. Fix the DB, then `npx prisma migrate resolve --rolled-back <name>`. |
| Links from Claude point to localhost | Set `APP_URL` on Render and redeploy. |
| `/` returns "No web build found" | The web build didn't run. Check the build logs for `vite build`. |
